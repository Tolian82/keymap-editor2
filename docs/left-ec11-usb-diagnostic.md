# Charybdis LEFT EC11 — диагностическое USB-журналирование

Эта ветка — временный инструмент поиска причины пропадания прокрутки, **не релиз**.
База: последний проверенный пользовательский вариант `3d5a8c4` (Actions 42513382079).

Функциональные параметры ZMK (колесо, PMW3610, BLE, клавиши, макросы,
`sensor-bindings`, таймеры и конфигурация правой половины) **не меняются**.
Только в `charybdis_left.conf` включены `CONFIG_ZMK_USB_LOGGING=y`,
`CONFIG_SENSOR_LOG_LEVEL_DBG=y`, `CONFIG_ZMK_LOG_LEVEL_DBG=y`.
Штатная CDC ACM виртуальная последовательная консоль на USB **левой половины**
позволяет наблюдать строки EC11 `prev/new`, `Delta` и события ZMK.

**Важно:** логирование само по себе меняет энергопотребление и нагрузку на
контроллер. Отсутствие ошибки под отладочной прошивкой также является
диагностическим результатом, но не доказательством устранения причины.

## Как собирать и проверять

1. В GitHub Actions выбранной ветки дождаться SUCCESS. Перепрошить **только
   LEFT** файлом `charybdis_left-nice_nano_v2-zmk.uf2`. Правую оставить из
   Actions 42513382079. **Не прошивать settings_reset**.
2. Кабель LEFT, как и раньше, подключён к Windows для питания; теперь он
   также должен показать виртуальный COM-порт. Зайдите в Диспетчер устройств →
   Порты (COM и LPT); найдите новый USB Serial Device (COMx), появляющийся при
   подключении LEFT. Если COM не появился — остановиться и проверить логи
   сборки/драйвер, не продолжать слепую диагностику.
3. Открыть COM-порт в PuTTY (Connection type: Serial), скорость 115200,
   включить Session → Logging → All session output в файл.
   Подключиться и вращать колесо до пропадания скроллинга.
4. Посмотреть, продолжают ли появляться строки `EC11` `Delta` при
   физическом вращении колеса после исчезновения скроллинга.
   Для отправки лога закройте PuTTY и передайте текстовый файл.
   **Логи могут содержать BLE-адреса или метаданные; проверьте файл перед
   публикацией в открытом GitHub.**
5. Если лог EC11 пропадает, основная проверка — GPIO/питание/IRQ и очередь
   исполнения драйвера LEFT. Если `Delta` продолжает появляться, переходить
   к подписке на GATT sensor notification справа, а не менять ZMK keymap.
   Если в логах есть `EC11`, но только `Delta: 0`, проверить электрические
   контакты/энкодер и правильность подсчёта квадратуры.

Снимки логов с обеих сторон нужны **только после** того, как этот тест
покажет, что сигнал доходит до левого драйвера.

Вернуться к оригинальной LEFT UF2 (SHA-256
`9eef19d7138cfe3c7acff26d1a562ca7a55d6463599c0a4c1bd12e86b383b6a0`)
после эксперимента. Не сливать диагностическую ветку в `main`.
